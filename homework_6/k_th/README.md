# Задача 3. K-th

Найти k-й по величине элемент массива, не сортируя массив целиком и не используя кучи.

| `nums` | `k` | Ответ |
|---|---|---|
| `[3, 2, 1, 5, 6, 4]` | 2 | 5 |
| `[3, 2, 3, 1, 2, 4, 5, 5, 6]` | 4 | 4 |
| `[5, 5, 3, 1]` | 2 | 5 |

Принятые соглашения:

- `k` считается с единицы, `k = 1` - максимум;
- повторяющиеся значения - **отдельные позиции**, как во втором примере: для
  `[3, 2, 3, 1, 2, 4, 5, 5, 6]` по убыванию идут `6, 5, 5, 4, ...`, и четвертый элемент - 4, а
  не 3 (четвертое различное значение);
- при `k < 1`, `k > len(nums)` и пустом массиве - `ValueError`;
- `k` должен быть целым числом (`int`, но не `bool`); для дробных значений, строк,
  `None` и других нецелочисленных типов - `TypeError`;
- `nums` не меняется, функция работает с копией.

## Идея решения

Если отсортировать массив по возрастанию, k-й по величине элемент окажется на позиции
`target = n - k` (максимум на позиции `n - 1`, второй по величине на `n - 2` и т.д.; равные
значения занимают разные позиции). Значит, нужен элемент, который стоял бы на позиции `target`
после сортировки, то есть порядковая статистика.

Quickselect разбивает массив так же, как quicksort, но после разбиения продолжает только в той
части, где лежит `target`. Вторая часть больше не нужна, поэтому массив целиком не сортируется.

```python
target = n - k
low, high = 0, n - 1
while True:
    pivot = arr[(low + high) // 2]
    lt, gt = partition3(arr, low, high, pivot)
    if target < lt:
        high = lt - 1
    elif target > gt:
        low = gt + 1
    else:
        return pivot
```

`partition3` - трехчастное разбиение (флаг Дейкстры): после него `arr[low..lt-1] < pivot`,
`arr[lt..gt] == pivot`, `arr[gt+1..high] > pivot`. Один проход с тремя указателями: элемент
меньше pivot меняется с `arr[lt]` и обе границы сдвигаются; больше - меняется с `arr[gt]`, и `i`
**не** сдвигается, потому что пришедший с конца элемент еще не просмотрен; равный просто
пропускается.

### Почему такие выбор pivot и разбиение

- **Трехчастное разбиение, а не `partition` из задачи 1.** У разбиения Ломуто с `<` все элементы,
  равные pivot, уходят вправо. На массиве из одинаковых значений отрезок каждый раз уменьшается на
  один элемент, и поиск становится квадратичным (то же самое было с `quick_sort` на `equal` в
  задаче 1). Здесь весь блок равных pivot выбрасывается за один шаг, а если `target` попал в этот
  блок, ответ найден сразу.
- **Pivot - средний элемент отрезка.** На отсортированном и обратном массивах это точная медиана,
  поэтому они не дают худшего случая, в отличие от pivot = последний элемент. Случайный pivot
  дал бы оценку среднего случая для любого входа, но тогда пошаговая таблица зависела бы от
  генератора случайных чисел; средний элемент делает работу детерминированной.
- **Итеративно.** Рекурсия здесь хвостовая, ее естественно заменить циклом по `low`, `high`: нет
  ни ограничения глубины рекурсии, ни стека.

## Почему алгоритм корректен

Пусть `s` - массив `nums`, отсортированный по возрастанию (он нужен только для рассуждения).
Инвариант в начале каждой итерации:

1. `low <= target <= high`;
2. на позициях `low..high` в `arr` лежат ровно те элементы, которые в `s` стоят на позициях
   `low..high` (в любом порядке).

В начале `low = 0`, `high = n - 1`, и оба пункта верны.

После `partition3` на отрезке `lt - low` элементов меньше pivot, `gt - lt + 1` равных и остальные
больше. По пункту 2 это значит, что `s[low..lt-1]` - ровно элементы меньше pivot, `s[lt..gt]` все
равны pivot, `s[gt+1..high]` - элементы больше pivot.

- Если `lt <= target <= gt`, то `s[target] = pivot`, и ответ верен.
- Если `target < lt`, искомый элемент среди `arr[low..lt-1]`, а это ровно `s[low..lt-1]`.
  Отброшенная часть `arr[lt..high]` содержит только элементы `s[lt..high]`, то есть **не содержит
  искомой порядковой статистики**. После `high = lt - 1` инвариант сохраняется.
- Случай `target > gt` симметричен.

**Завершение.** Pivot берется из самого отрезка, поэтому блок `lt..gt` не пуст, и каждая итерация
уменьшает отрезок хотя бы на 1. По пункту 1 отрезок никогда не становится пустым, значит не позже
чем через `n` итераций `target` окажется в блоке `lt..gt`. Все обращения к `arr` идут по индексам
из `low..high`, за границы массива алгоритм не выходит.

## Сложность

`partition3` на отрезке длины `m` делает ровно `m` итераций цикла (каждая сдвигает `i` вперед или
`gt` назад) и не больше двух сравнений на итерацию: O(m). Время всего поиска - сумма длин
отрезков по всем шагам.

- **Лучший случай Θ(n)**: например, все элементы равны - одно разбиение. Меньше `n` быть не может:
  нужно хотя бы скопировать массив и разбить его один раз.
- **Средний случай O(n).** Предположим, что pivot - случайный элемент отрезка, так бывает при
  случайном порядке входа. С вероятностью не меньше 1/2 он лежит в средней половине по величине,
  и тогда оставшийся отрезок не длиннее `3m/4`. Ожидаемое число шагов до такого удачного не больше
  2, поэтому ожидаемое время не больше `2 (n + 3n/4 + (3/4)² n + ...) = 8n`, то есть O(n).
  Повторы только помогают: весь блок равных pivot отбрасывается сразу.
- **Худший случай Θ(n²)**: pivot каждый раз минимум или максимум отрезка, а `target` на другом
  конце. Тогда отрезок уменьшается на 1, и работа `n + (n - 1) + ... + 1 = n(n + 1)/2`. Для pivot
  = средний элемент такие входы существуют (тест строит его для `n = 500`: 500 шагов), но
  отсортированный, обратный и постоянный массивы к ним не относятся. На них, а также на
  случайных массивах из 100 000 элементов, тест получает не больше нескольких десятков шагов
  для `k = 1, n/3, n/2, n`.
- **Память.** Копия входа O(n) - чтобы не менять `nums`. Рабочая память сверх копии **O(1)**:
  `low`, `high`, `lt`, `gt`, `i`, `pivot`; рекурсии и стека нет. Если разрешить портить вход,
  копию можно убрать, и дополнительная память будет O(1).

**Замечание о журнале.** Все оценки выше относятся к вызову без `log` (`log=None`).
При включенном журнале после каждого из `t` разбиений копируется весь массив длины `n`: это
дополнительно O(n · t) времени и памяти (в худшем случае O(n²)). Журнал нужен для
пошаговой визуализации, а не для обычного поиска.

## Пример работы

Квадратные скобки - блок `lt..gt` равных pivot элементов после разбиения. `target = n - k`.
Таблицы напечатаны `python main.py`, совпадение проверяет тест `test_readme_matches_program`.

**Второй пример из условия** - с повторами, ответ находится только на третьем шаге, поиск
сначала уходит вправо, потом влево:

| Шаг | low | high | pivot | lt..gt | target | Массив после разбиения | Дальше |
|---|---|---|---|---|---|---|---|
| 1 | 0 | 8 | 2 | 1..2 | 5 | `1 [2 2] 3 4 5 5 6 3` | вправо: low = 3 |
| 2 | 3 | 8 | 5 | 6..7 | 5 | `1 2 2 3 4 3 [5 5] 6` | влево: high = 5 |
| 3 | 3 | 5 | 4 | 5..5 | 5 | `1 2 2 3 3 [4] 5 5 6` | ответ 4 |

- Шаг 1: pivot `arr[4] = 2`. Обе двойки попадают в блок `1..2`, слева только единица. `target = 5`
  правее блока, поэтому позиции `0..2` отбрасываются: там три наименьших элемента.
- Шаг 2: отрезок `3..8`, pivot `arr[5] = 5`. Обе пятерки встают на `6..7`, шестерка на 8.
  `target = 5 < 6`, отбрасываются `6..8`.
- Шаг 3: отрезок `3..5` = `{3, 4, 3}`, pivot `arr[4] = 4` встает на позицию 5 = `target`. Ответ 4.

**Первый пример из условия**:

| Шаг | low | high | pivot | lt..gt | target | Массив после разбиения | Дальше |
|---|---|---|---|---|---|---|---|
| 1 | 0 | 5 | 1 | 0..0 | 4 | `[1] 2 5 6 4 3` | вправо: low = 1 |
| 2 | 1 | 5 | 6 | 5..5 | 4 | `1 2 5 4 3 [6]` | влево: high = 4 |
| 3 | 1 | 4 | 5 | 4..4 | 4 | `1 2 4 3 [5] 6` | ответ 5 |

На шаге 1 pivot оказался минимумом, на шаге 2 - максимумом: это пример неудачных разбиений, при
которых отрезок уменьшается всего на 1. Четверка и тройка на позициях 2..3 так и остались в
неправильном порядке: для ответа это не нужно.

**`target` внутри блока повторов** (`[5, 5, 3, 1]`, `k = 2`):

| Шаг | low | high | pivot | lt..gt | target | Массив после разбиения | Дальше |
|---|---|---|---|---|---|---|---|
| 1 | 0 | 3 | 5 | 2..3 | 2 | `3 1 [5 5]` | ответ 5 |

Обе пятерки занимают позиции `2..3`, `target = 2` попадает в блок: ответ 5 уже на первом шаге.
Первая пятерка - первый по величине элемент, вторая - второй.
