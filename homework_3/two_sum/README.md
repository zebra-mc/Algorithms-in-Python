# Задача 1. Two sum

Дан массив целых чисел `arr` и целое число `k`. Нужно найти индексы двух элементов,
сумма которых равна `k`. Гарантируется, что такая пара ровно одна. Ответ - два индекса
в порядке возрастания.

| Вход | Выход |
|---|---|
| `arr = [1, 3, 4, 10]`, `k = 7` | `1, 2` |
| `arr = [5, 5, 1, 4]`, `k = 10` | `0, 1` |

|---|---|


Пример запуска:

```

Введите k: 7
1, 2
```

Если ввод не целые числа или пар с суммой `k` не ровно одна, программа пишет, что не так,
а не падает.

## Объяснение решения

### Идея

Наивно можно перебрать все пары `i < j`, это `n * (n - 1) / 2` проверок, то есть O(n²).

Ускорение держится на простом наблюдении: если второй элемент пары стоит на позиции `j`,
то первый обязан быть равен `k - arr[j]`. Значит для каждого `j` вопрос "есть ли ему пара"
превращается в вопрос "встречалось ли значение `k - arr[j]` левее". На такой вопрос словарь
отвечает в среднем за O(1).

Отсюда алгоритм: идем по массиву один раз и держим словарь `seen`: значение -> индекс.
Для очередного `x = arr[i]` считаем `need = k - x`.

- если `need` есть в `seen`, то `arr[seen[need]] + arr[i] = need + x = k`, возвращаем `(seen[need], i)`;
- иначе кладем `seen[x] = i` и идем дальше.

### Почему это правильно

**Инвариант.** Перед шагом `i` в `seen` лежат ровно значения `arr[0..i-1]`, и каждый ключ
указывает на индекс, где это значение действительно стоит (на последнее вхождение).

**Пара не пропускается.** Пусть ответ `p < q`. К шагу `q` элемент `arr[p]` уже в `seen`
(по инварианту), поэтому на шаге `q` проверка сработает. Остановиться раньше алгоритм не может:
любая остановка на шаге `i` дает настоящую пару с суммой `k`, а она по условию одна.

**Индексы сразу по возрастанию.** В `seen` только индексы левее текущего, значит `seen[need] < i`.
Сортировать ответ не нужно.

**Элемент не складывается сам с собой.** `x` попадает в `seen` только после проверки. Для
`k = 10` и одиночной пятерки на ее шаге `need = 5` в `seen` еще нет. А две разные пятерки
(пример `5 5 1 4`) дают `0, 1`: первая уже в `seen`, когда проверяем вторую.

**Повторы значений.** При повторе `seen[x]` перезаписывается новым индексом. На ответ это не влияет:
если бы нужное значение стояло левее `q` в двух местах, пар с суммой `k` было бы две.

### Проверка условия

В `main.py` условие задачи проверяет `count_pairs`. Это тот же прием со словарем, только
словарь хранит не индекс, а сколько раз значение встретилось, и на каждом `x` к ответу
прибавляется `count[k - x]` - число пар, которые `x` замыкает. Получается число пар `i < j`
с суммой `k` за O(n).

Самому `two_sum` эта проверка не нужна: условие гарантирует, что пара ровно одна. Но с клавиатуры
можно ввести массив, где пар нет или их несколько, и тогда `two_sum` вернул бы `None` или одну из
пар без предупреждения. Поэтому `main` сначала проверяет условие, а потом решает задачу. Это
второй проход по массиву, но асимптотика остается O(n).

## Оценка сложности

Обозначения: `n` - длина массива.

| | `two_sum` | перебор пар |
|---|---|---|
| время | O(n) в среднем | O(n²) |
| память | O(n) | O(1) |

### Время

Один проход, на каждом элементе вычитание, `need in seen` и `seen[x] = i`.
Операции со словарем в Python (хеш-таблица) в среднем стоят O(1), поэтому весь проход O(n).

Оценка именно средняя. Если у многих чисел совпадает `hash()`, одна операция со словарем
стоит O(n), и весь проход O(n²). Для целых чисел это можно подстроить специально: `hash(x)`
равен остатку от деления `x` на `2^61 - 1` (и еще `hash(-1) == hash(-2)`), поэтому у чисел
`0, 2^61 - 1, 2 * (2^61 - 1), ...` хеш одинаковый. На обычных данных такого не бывает.
Ответ при совпадении хешей остается верным, словарь сравнивает сами ключи (тест `test_equal_hashes`).

`count_pairs` тоже O(n), так что проверка ввода асимптотику не портит.

### Память

В худшем случае пара находится на последнем элементе, и в `seen` к этому моменту
лежат все предыдущие значения, до `n - 1` штук: O(n). То есть скорость куплена дополнительной
памятью. `count_pairs` тоже хранит до `n` значений.

## Визуализация работы алгоритма

Пример: `arr = [7, 2, 7, -3, 11, 5]`, `k = 8`. Он нетривиальный: семерка повторяется,
а пара находится только на пятом шаге. Все строки таблицы проверяет тест
`TestReadmeExample.test_states` через функцию `trace`.

| i | x | need = k - x | seen после шага | Что происходит |
|---:|---:|---:|---|---|
| - | - | - | `{}` | начало |
| 0 | 7 | 1 | `{7: 0}` | 1 в seen нет, запоминаем 7 -> 0 |
| 1 | 2 | 6 | `{7: 0, 2: 1}` | 6 в seen нет, запоминаем 2 -> 1 |
| 2 | 7 | 1 | `{7: 2, 2: 1}` | 1 в seen нет, 7 уже был под 0, индекс обновили на 2 |
| 3 | -3 | 11 | `{7: 2, 2: 1, -3: 3}` | 11 в seen нет, запоминаем -3 -> 3 |
| 4 | 11 | -3 | `{7: 2, 2: 1, -3: 3}` | **-3 есть в seen под индексом 3, пара найдена** |

Элемент `5` с индексом 5 не просматривается: алгоритм останавливается на шаге 4.

```
индекс:   0    1    2    3    4    5
arr:      7    2    7   -3   11    5
                         ^    ^
                         |    i = 4, x = 11, need = 8 - 11 = -3
                         seen[-3] = 3

arr[3] + arr[4] = -3 + 11 = 8   ->   ответ: 3, 4
```

Второй пример из условия, `arr = [5, 5, 1, 4]`, `k = 10`, показывает, почему `x` кладется
в `seen` после проверки:

| i | x | need = k - x | seen после шага | Что происходит |
|---:|---:|---:|---|---|
| - | - | - | `{}` | начало |
| 0 | 5 | 5 | `{5: 0}` | 5 в seen еще нет (сама себе не пара), запоминаем 5 -> 0 |
| 1 | 5 | 5 | `{5: 0}` | **5 есть в seen под индексом 0, пара найдена: `0, 1`** |
