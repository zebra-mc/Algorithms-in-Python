# Задача 1. Makeheap

Нужно преобразовать произвольный массив в двоичную minheap двумя способами: за O(n log n) и за O(n).
Обе функции `makeheap_n_log_n(arr)` и `makeheap(arr)` изменяют исходный список на месте и
возвращают его же. Допускаются одинаковые значения; для пустого списка результатом остается
пустой список. Предполагается, что ключи образуют обычный полный порядок (например,
целые числа). В `main.py` нет импортов: обе операции просеивания реализованы самостоятельно.

## Идея решения и корректность

Minheap — полное двоичное дерево, у которого ключ родителя не больше ключа любого из детей.
В массиве с нумерацией от нуля у узла `i` левый ребенок имеет индекс `2*i + 1`, правый — `2*i + 2`,
родитель (если `i > 0`) — `(i - 1) // 2`. Ребенок существует, если его индекс меньше размера кучи.
Из свойства minheap следует, что в корне находится минимальный элемент, но массив целиком
не обязан быть отсортированным.

### Последовательное построение: `makeheap_n_log_n`

Первые `i` элементов уже образуют minheap. Добавляем к ним `arr[i]` (он уже стоит на нужной
позиции массива), затем вызываем `sift_up(arr, i)`: пока добавленный элемент меньше родителя,
меняем их местами и продолжаем подъем.

**Инвариант.** Перед очередной итерацией `arr[:i]` — minheap, а `arr[i:]` еще не обработан.
При добавлении листа нарушиться может только ребро к его родителю. После обмена старый
родитель оказывается ниже и не нарушает свойства кучи там: до добавления он был не больше
всех потомков. Новый, меньший ключ может нарушить только следующее ребро вверх.
При остановке нарушений нет, поэтому `arr[:i+1]` — minheap. Начальный префикс длины один
уже является кучей; после последней итерации обработан весь массив.

### Построение снизу вверх: `makeheap`

Листья имеют индексы от `n // 2` до `n - 1` и сами по себе являются кучами. Обрабатываем только
внутренние узлы: `n // 2 - 1, ..., 0`. В каждом вызываем `sift_down(arr, root, n)`.
Если узел больше меньшего из своих детей, меняем его с этим ребенком и продолжаем спуск.
Если оба ребенка не меньше узла или детей нет, останавливаемся.

**Инвариант.** Перед обработкой узла `i` поддеревья всех узлов с индексами больше `i`
являются minheap. В частности, оба поддерева детей `i` уже исправлены. При обмене с меньшим
ребенком новое значение родителя не больше обоих детей; нарушение может остаться только
в поддереве, куда ушел прежний ключ. Спуск исправляет его по тому же правилу и обязательно
завершается, поскольку идет на один уровень вниз. Так после обработки `i` его поддерево
тоже является minheap. При `i = 0` это весь массив.

В обоих алгоритмах происходят только обмены, поэтому сохраняются все исходные элементы
и их кратности. Разный порядок обменов может давать разные корректные кучи.

## Оценка сложности

Здесь и далее `n` — длина массива, операции сравнения ключей и обмена считаем O(1).

### `makeheap_n_log_n`

Глубина элемента с индексом `i` равна `floor(log2(i + 1))`. Один `sift_up` может пройти
не более этой глубины. Для n ≥ 2:

```text
T(n) = O(n + sum_{i=1}^{n-1} floor(log2(i + 1)))
     = O(n log n).
```

На строго убывающем массиве каждый новый элемент меньше всех предыдущих и поднимается
до корня. Как минимум половина элементов имеет глубину порядка log n; суммарно это
Ω(n log n). Поэтому время Θ(n log n) именно в худшем случае; O(n log n) — верхняя
оценка, а не утверждение о времени на каждом входе. На уже готовой minheap, в том числе
на возрастающем массиве и на одинаковых элементах, каждый подъем завершается сразу,
так что время Θ(n). На случайных данных из эксперимента многие подъемы заканчиваются быстро,
поэтому наблюдаемое время ближе к линейному. Это не гарантия для произвольного входа
и не доказательство средней асимптотики без указания распределения входных данных.

### Доказательство O(n) для `makeheap`

Оценка O(n log n), полученная умножением n узлов на максимальную высоту дерева, слишком груба:
большинство узлов находится возле листьев. Учтем высоту каждого узла отдельно.

Обозначим через `h(i)` высоту поддерева узла `i` — число ребер на самом длинном пути от него
до листа. Стоимость `sift_down` в узле `i` не превышает O(1 + h(i)). На каждом пройденном
уровне производится не более двух сравнений ключей (выбор меньшего ребенка и сравнение с ним).

В массивном представлении индекс самого левого потомка на расстоянии `d` ребер от `i` равен
`(i + 1) * 2^d - 1` (получается d последовательными переходами `j -> 2*j + 1`).
Так как дерево полное, узел имеет высоту не меньше `d` тогда и только тогда, когда этот индекс
меньше `n`. Следовательно,

```text
h(i) >= d  <=>  (i + 1) * 2^d <= n.

Число узлов высоты >= d: floor(n / 2^d).
```

Теперь аккуратно выпишем сумму. Каждый узел высоты `h` учитывается один раз для каждого
`d = 1, 2, ..., h`, то есть ровно h раз. Поменяем порядок конечного суммирования.
При `n >= 1` положим `H = floor(log2(n))`:

```text
S = sum_{i=0}^{n-1} h(i)
  = sum_{i=0}^{n-1} sum_{d=1}^{h(i)} 1
  = sum_{d=1}^{H} |{ i : h(i) >= d }|
  = sum_{d=1}^{H} floor(n / 2^d)
 <= n * sum_{d=1}^{H} (1 / 2^d)
  = n * (1 - 1 / 2^H)
  < n.
```

Последняя формула — сумма конечной геометрической прогрессии со знаменателем 1/2.
Доказательство не предполагает, что последний уровень заполнен целиком.

Таким образом, суммарно не более `2*S < 2*n` сравнений ключей при просеиваниях;
плюс O(n) на обход `floor(n/2)` внутренних узлов. Итого:

```text
T(n) = O(floor(n/2) + S) = O(n).
```

Цикл всегда обрабатывает `floor(n/2)` узлов, поэтому при n ≥ 2 есть и нижняя оценка Ω(n).
Время `makeheap` равно Θ(n) на любом массиве. Пустой и одноэлементный массивы обрабатываются
за O(1).

### Память и итог

| Алгоритм | Время в худшем случае | Время на готовой куче | Дополнительная память |
|---|---|---|---|
| `makeheap_n_log_n` | Θ(n log n) | Θ(n) | O(1) |
| `makeheap` | Θ(n) | Θ(n) | O(1) |

Просеивания итеративные, элементы меняются в исходном списке, дополнительной структуры
или стека рекурсии нет. Оценки относятся к обычному вызову без `log`. Если включить
визуализацию, для каждого шага сохраняется снимок всего массива, что требует O(n²)
дополнительной памяти и времени для логирования; это не часть основного алгоритма.

## Визуализация

Исходный массив `[9, 4, 7, 1, 0, 3, 2, 1]`: есть повтор единицы, неполный последний уровень,
несколько подъемов и спусков.

### Последовательные вставки

Слева от `/` — уже построенная куча, справа — еще не обработанные элементы.
В начальный момент куча состоит только из `9`.

| Шаг | Действие | Массив |
|---|---|---|
| 0 | начало | `[9, 4, 7, 1, 0, 3, 2, 1]` |
| 1 | sift_up(1) | `[4, 9] / [7, 1, 0, 3, 2, 1]` |
| 2 | sift_up(2) | `[4, 9, 7] / [1, 0, 3, 2, 1]` |
| 3 | sift_up(3) | `[1, 4, 7, 9] / [0, 3, 2, 1]` |
| 4 | sift_up(4) | `[0, 1, 7, 9, 4] / [3, 2, 1]` |
| 5 | sift_up(5) | `[0, 1, 3, 9, 4, 7] / [2, 1]` |
| 6 | sift_up(6) | `[0, 1, 2, 9, 4, 7, 3] / [1]` |
| 7 | sift_up(7) | `[0, 1, 2, 1, 4, 7, 3, 9] / []` |

### Построение снизу вверх

| Шаг | Действие | Массив |
|---|---|---|
| 0 | начало | `[9, 4, 7, 1, 0, 3, 2, 1]` |
| 1 | sift_down(3) | `[9, 4, 7, 1, 0, 3, 2, 1]` |
| 2 | sift_down(2) | `[9, 4, 2, 1, 0, 3, 7, 1]` |
| 3 | sift_down(1) | `[9, 0, 2, 1, 4, 3, 7, 1]` |
| 4 | sift_down(0) | `[0, 1, 2, 1, 4, 3, 7, 9]` |

На шаге 4 ключ `9` опускается по индексам `0 -> 1 -> 3 -> 7`, при этом уже исправленные
поддеревья позволяют выбрать нужного ребенка. Получилась другая minheap с тем же набором ключей.

Таблицы печатает `python main.py`; совпадение проверяет `test_readme_matches_program`.

## Сравнение времени

Измерения выполнены в среде CPython 3.13.5, Linux x86_64. Используются массивы длины
1 000, 10 000 и 100 000: `random` — псевдослучайные целые из `[0, 10*n)` (seed = 7),
`reversed` — строго убывающий массив; дополнительно `sorted` — возрастающий и `equal` —
из одинаковых элементов. Для каждого алгоритма один прогрев и семь измерений
`time.perf_counter()`, в таблице медиана. Порядок алгоритмов циклически меняется.
Одинаковый исходный массив копируется перед каждым запуском вне замера; проверка minheap
и сохранения всех значений тоже вне замера. Логирование отключено.

| Массив | n | makeheap_n_log_n, мс | makeheap, мс | Отношение |
|---|---:|---:|---:|---:|
| random | 1000 | 0.216 | 0.184 | 1.17 |
| random | 10000 | 2.454 | 1.912 | 1.28 |
| random | 100000 | 25.153 | 19.576 | 1.28 |
| reversed | 1000 | 0.722 | 0.201 | 3.58 |
| reversed | 10000 | 11.039 | 2.196 | 5.03 |
| reversed | 100000 | 149.984 | 23.094 | 6.49 |
| sorted | 100000 | 9.763 | 8.900 | 1.10 |
| equal | 100000 | 9.534 | 8.661 | 1.10 |

«Отношение» — время первого способа, деленное на время второго.

**Выводы.** На убывающих массивах, где последовательные вставки дают худший случай,
разница растет: примерно с 3,58 до 6,49 раза. При увеличении n в 100 раз `makeheap`
на этих данных замедляется примерно в 115 раз, а `makeheap_n_log_n` — в 208 раз.
На случайных данных выигрыш меньше (многие вставки не поднимаются до корня), а на
возрастающих и постоянных массивах оба алгоритма линейны. Эксперимент согласуется с доказанной
оценкой, но сам по себе ее не доказывает. Абсолютное время зависит от машины и версии Python.

## Тесты

Обе функции проходят один набор тестов: проверяются не конкретная форма кучи, а свойство
родитель ≤ ребенок, корень-минимум, сохранение мультимножества и идентичность входного списка.

| Группа | Что проверяется |
|---|---|
| типичные и граничные | пустой, один и два элемента, повторы, отрицательные и дробные значения, длины около степеней двойки |
| систематические | все массивы длины до 6 из {-1, 0, 1}, 300 случайных, случайный и убывающий массивы по 100 000 элементов |
| ограничения | подмена `sorted` и операций `heapq`; `sift_down` не затрагивает элементы за границей `size` |
| асимптотика | счетчик сравнений на убывающих массивах: точная сумма глубин у первого алгоритма и верхняя граница `2*S` у второго |
| визуализация | инвариант префикса или обработанных поддеревьев после каждого шага, сохранение элементов, совпадение таблиц с README |
