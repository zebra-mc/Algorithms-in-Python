# Задача 1. Tracer

Нужно реализовать декоратор, который показывает стек вызовов рекурсивной функции. На каждом шаге
должны быть видны вход в рекурсию (вызов с аргументами), отступ по глубине стека и возврат из
рекурсии с результатом.

```python
from main import tracer

@tracer
def factorial(n):
    if n <= 1:
        return 1
    return n * factorial(n - 1)

factorial(3)
```

```text
→ factorial(3)
  → factorial(2)
    → factorial(1)
    ← factorial(1) = 1
  ← factorial(2) = 2
← factorial(3) = 6
```

Формат строк:

| Событие | Строка |
|---|---|
| вход в вызов | `<отступ>→ f(аргументы)` |
| возврат | `<отступ>← f(аргументы) = repr(результат)` |
| выход по исключению | `<отступ>← f(аргументы) ! ТипИсключения: сообщение` |

Отступ – два пробела на каждый открытый выше декорированный вызов. Аргументы печатаются через
`repr`, именованные – как `key=value`, то есть так, как вызов выглядел бы в коде.

## Файлы и запуск

| Файл | Что внутри |
|---|---|
| `main.py` | декоратор `tracer`, запись вызова `format_call`, примеры `factorial` и `fibonacci`, демонстрация `main` |
| `test_tracer.py` | тесты |
| `README.md` | объяснение, корректность, сложность, визуализация |

```

python -m unittest -v       # тесты, запускать из папки tracer

```

При `import main` ничего не печатается: демонстрация стоит под `if __name__ == "__main__"`.

## Объяснение решения

### Идея

`tracer(func)` возвращает обертку `wrapper(*args, **kwargs)`. Декоратор подменяет имя `factorial`
в модуле на обертку, поэтому рекурсивный вызов `factorial(n - 1)` внутри тела тоже проходит через
нее – тело функции менять не нужно. Каждый вызов обертки:

1. собирает строку вызова `format_call(...)` и запоминает текущий уровень `level = _depth`;
2. печатает строку входа с отступом `INDENT * level`;
3. увеличивает `_depth` и вызывает исходную `func(*args, **kwargs)` – все вложенные вызовы
   печатаются уже на уровне `level + 1`;
4. в `finally` уменьшает `_depth` – при обычном возврате и при любом исключении;
5. печатает строку возврата с тем же отступом и возвращает результат без изменений. Если `func`
   бросила `Exception`, печатается строка выхода с `!` и исключение пробрасывается дальше
   (`raise`), а не подавляется.

`functools.wraps` переносит в обертку `__name__`, `__doc__` и ссылку `__wrapped__` на исходную
функцию.

Строка вызова считается один раз, на входе. Если функция изменит изменяемый аргумент (например,
выкинет элемент из списка), строка возврата все равно совпадет со строкой входа, и пару
«вход – выход» легко найти глазами (тест `test_mutable_argument`).

### Где хранить глубину

`_depth` – одна переменная модуля, общая для всех декорированных функций. Альтернативы:

| Способ | Почему не выбран |
|---|---|
| свой счетчик в замыкании каждой обертки (`nonlocal`) | при взаимной рекурсии `is_even` → `is_odd` у второй функции свой счетчик равен 0, и вложенность теряется |
| передавать глубину аргументом | требует менять сигнатуру и тело каждой трассируемой функции, а декоратор должен работать с готовой функцией без правок |
| считать кадры через `inspect.stack()` | O(глубина стека) на каждый вызов и учитывает чужие, недекорированные кадры |
| `sys.settrace` | глобальный хук на все функции программы, замедляет весь код; условие прямо решается декоратором |

Общий счетчик – самый простой из полностью корректных вариантов: он одинаково работает для одной
рекурсивной функции, для нескольких функций подряд и для взаимной рекурсии (тест
`test_mutual_recursion`).

### Почему это правильно

**Инвариант.** Вне выполнения обертки `_depth` равен числу вызовов оберток, которые начались и
еще не закончились, то есть числу декорированных вызовов на стеке.

- Вне любых вызовов таких вызовов нет и `_depth = 0` – значение при импорте модуля.
- Вход: обертка запоминает `level = _depth` – это число открытых предков текущего вызова, то есть
  его глубина в дереве вызовов (у корня 0). Строка входа печатается с отступом `level`. Затем
  `_depth` становится `level + 1`, потому что открылся еще один вызов, – инвариант сохранен.
- Выход: блок `finally` выполняется при любом завершении `func` – по `return` и по исключению,
  в том числе `RecursionError` или `KeyboardInterrupt`. По предположению индукции все дочерние
  вызовы к этому моменту уже вернули `_depth` к `level + 1`, и после `-1` он снова `level` –
  ровно столько вызовов осталось открыто.

**Следствия.**

- Отступ каждой строки равен глубине вызова: вход и выход печатаются с одним и тем же `level`.
- Порядок строк совпадает с порядком событий: строка входа печатается до вызова `func`, строка
  выхода – после ее завершения, поэтому строки потомков всегда стоят между входом и выходом
  родителя, а братья идут подряд на одном уровне (ветвящаяся рекурсия).
- После внешнего вызова `_depth` снова 0, и повторный запуск или вызов другой функции начинается
  с нулевого уровня, даже если предыдущий завершился исключением.
- Результат не меняется: обертка возвращает тот же объект, что вернула `func`, и не трогает
  аргументы.

Проверено и на переполнении стека: после `RecursionError` в `factorial(600)` значение `_depth`
снова равно 0.

## Оценка сложности

Обозначения:

- `C` – число вызовов декорированных функций за один внешний вызов;
- `h` – максимальная глубина рекурсии (число одновременно открытых декорированных вызовов);
- `d_i` – глубина `i`-го вызова, `d_i < h`;
- `a_i` и `r_i` – длина текстов `repr` аргументов и результата `i`-го вызова;
- `T_f` – время самой функции без декоратора.

Для `factorial(n)`: `C = n`, `h = n`. Для `fibonacci(n)`: `C = 2F(n+1) - 1 = Θ(φⁿ)`, `h = n`.

### Время

На один вызов обертка тратит:

- O(1) на учет глубины, `try/finally` и передачу аргументов;
- O(`a_i`) на `format_call`, если `repr` аргументов работает за время, пропорциональное длине
  своего текста (для чисел, строк и списков это так или почти так);
- O(`d_i + a_i`) на строку входа и O(`d_i + a_i + r_i`) на строку возврата – отступ из `d_i`
  повторений `INDENT` тоже строится и печатается.

Итого `T_f + O(Σ (d_i + a_i + r_i))`, что не больше `T_f + O(C·h + Σ (a_i + r_i))`. Сказать
«трассировка стоит O(C)» можно только когда аргументы и результаты короткие и глубина
ограничена. Например, для `factorial(n)` одни отступы дают `Σ d_i = 0 + 1 + … + (n - 1) = Θ(n²)`
символов, а результаты – длинные числа: `r_i = Θ(i log i)` цифр, а перевод большого `int` в
десятичную строку в CPython работает за время, растущее быстрее числа цифр. Для `fibonacci(n)` трасса из `Θ(φⁿ)` строк
повторяет экспоненциальное время самой функции, а отступы добавляют множитель не больше `h = n`.

### Память

- Стек: на каждый уровень рекурсии к кадру `func` добавляется кадр `wrapper` – O(h), но с
  множителем 2 (см. «Ограничения»).
- Каждая открытая обертка хранит свою строку вызова и число `level`: O(Σ `a_i`) по открытым
  вызовам, то есть O(h·a) при длине аргументов до `a`. Строки отступа не хранятся, а строятся
  при печати.
- Временная строка одной печатаемой строки – O(h + a + r). Трасса не накапливается в памяти,
  каждая строка сразу уходит в `print`.

## Визуализация

Пример – `fibonacci(4)`, ветвящаяся рекурсия. Дерево вызовов (`F(k)` – `fibonacci(k)`, справа
от `=` – возвращаемое значение):

```text
                 F(4) = 3
               /          \
        F(3) = 2            F(2) = 1
        /      \            /      \
   F(2) = 1   F(1) = 1  F(1) = 1  F(0) = 0
   /      \
F(1) = 1  F(0) = 0
```

Фактический вывод `python main.py` для этого вызова (этот же текст сверяет с программой тест
`test_readme_matches_program`, а тест `test_fibonacci` – с вручную выписанным эталоном):

```text
→ fibonacci(4)
  → fibonacci(3)
    → fibonacci(2)
      → fibonacci(1)
      ← fibonacci(1) = 1
      → fibonacci(0)
      ← fibonacci(0) = 0
    ← fibonacci(2) = 1
    → fibonacci(1)
    ← fibonacci(1) = 1
  ← fibonacci(3) = 2
  → fibonacci(2)
    → fibonacci(1)
    ← fibonacci(1) = 1
    → fibonacci(0)
    ← fibonacci(0) = 0
  ← fibonacci(2) = 1
← fibonacci(4) = 3
```

Как читать:

1. Выражение `fibonacci(n - 1) + fibonacci(n - 2)` вычисляется слева направо, поэтому вся левая
   ветка `F(3)` заканчивается раньше, чем начинается правая `F(2)`. Это обход дерева в глубину.
2. Самая глубокая точка – `F(1)` и `F(0)` под `F(2)` под `F(3)`: отступ 6 пробелов, уровень 3,
   на стеке одновременно `F(4) → F(3) → F(2) → F(1)`, `h = 4`.
3. Возвраты идут снизу вверх: `F(2)` получает `1 + 0 = 1`, затем `F(3)` – `1 + 1 = 2`, правая
   ветка `F(2)` снова дает `1`, и корень возвращает `2 + 1 = 3`.
4. Строк 18 = 2 · 9: по входу и выходу на каждый из `C = 2F(5) - 1 = 9` вызовов. `F(2)`
   вычисляется дважды, `F(1)` – трижды: трассировка наглядно показывает, откуда у наивного
   Фибоначчи экспоненциальное время.

`python main.py` печатает также трассировку `factorial(4)` – линейную рекурсию, где каждая строка
входа сдвинута на два пробела относительно предыдущей, а возвраты идут в обратном порядке.

## Тесты

`python -m unittest -v` из папки `tracer`. Вывод перехватывается через `redirect_stdout` и
`io.StringIO`, ввод с клавиатуры не нужен.

| Группа | Что проверяется |
|---|---|
| точный текст | `factorial(3)`, `fibonacci(4)` и базовые случаи сравниваются построчно с выписанными вручную эталонами |
| результаты | `fibonacci(0..11)` – с таблицей чисел, `factorial(1..14)` – с `math.factorial`; тип результата не меняется |
| структура | функция `check_nesting` по одному тексту ведет свой стек: отступ входа = 2 · (число открытых вызовов), каждый выход закрывает последний вход с той же записью и тем же отступом, в конце стек пуст; число вызовов сверяется с формулами `2F(n+1) - 1` и `n` |
| состояние | повторный запуск дает тот же текст и `_depth == 0`; несколько функций подряд начинают с нуля; взаимная рекурсия `is_even`/`is_odd` вложена правильно |
| исключения | `fall(2)` пробрасывает `ValueError`, печатает три строки выхода с `!`, сбрасывает глубину; в `risky` исключение перехватывается внутри рекурсии, и следующий дочерний вызов печатается на правильном уровне |
| аргументы | позиционные, по умолчанию и keyword-only (`countdown(3, step=2, label='x')`), результат `None`, строковый результат, изменяемый аргумент |
| модуль | `__name__`, `__doc__`, `__wrapped__`; `import main` в отдельном процессе ничего не печатает; трасса из README совпадает с выводом программы |

Тесты проверены на намеренно испорченных копиях `main.py`: уменьшение глубины без `finally`,
увеличение глубины до печати строки входа, пропущенное уменьшение, подавление исключения и
отсутствие `functools.wraps` – каждая из этих ошибок роняет от 1 до 13 тестов.

## Ограничения

- Каждый уровень занимает два кадра Python (обертка и сама функция), поэтому до `RecursionError`
  доходит примерно вдвое меньшая глубина: при лимите 1000 `factorial(480)` работает, а
  `factorial(500)` – уже нет. Состояние при этом не портится.
- Глубина хранится в одной переменной модуля, поэтому параллельные вызовы из нескольких потоков
  или корутин перемешали бы отступы. Условие этого не требует; для потоков счетчик можно было бы
  хранить в `threading.local`.
- Отступ учитывает только декорированные вызовы: недекорированная функция между ними уровня
  не добавляет.
- Для печати используются `repr` аргументов и результата: для очень больших объектов строки
  длинные и дорогие (см. «Сложность»).
- Печатается `__name__`, а не `__qualname__`: для методов класса имя короче, но без имени класса.
