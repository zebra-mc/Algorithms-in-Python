# Задача 3. Balanced Binary Tree

Нужно определить, является ли бинарное дерево сбалансированным по высоте: для **каждого** узла
высоты левого и правого поддеревьев отличаются не больше чем на 1. Ответ – `True` или `False`.

Дерево произвольное, не обязательно BST: значения в узлах могут быть любыми, повторяться
и не быть упорядоченными. Ответ зависит только от формы дерева.

## Файлы и запуск

| Файл | Что внутри |
|---|---|
| `main.py` | класс узла `TreeNode`, обход снизу вверх `postorder_heights`, проверка `is_balanced`, короткий пример запуска |
| `test_balanced_binary_tree.py` | тесты |
| `README.md` | объяснение, корректность, сложность, визуализация |

```
python main.py              # два дерева из раздела "Визуализация": False, True
python -m unittest -v       # тесты, запускать из папки задачи
```

Использование:

```python
from main import TreeNode, is_balanced

root = TreeNode(1, TreeNode(2, TreeNode(3)), TreeNode(4))
is_balanced(root)   # True: у корня высоты 2 и 1, у узла 2 – 1 и 0
```

## Объяснение решения

### Высота

Везде, в коде, тестах и таблицах ниже, высота считается в узлах:

- высота пустого дерева (`None`) равна 0;
- высота листа равна 1;
- h(node) = 1 + max(h(node.left), h(node.right)).

Тогда условие баланса для узла: |h_L – h_R| <= 1, где h_L и h_R – высоты его левого и правого
поддеревьев. Отсутствующий ребенок – это пустое поддерево высоты 0, отдельного случая для него нет.

### Почему не считать высоты для каждого узла заново

Самый прямой способ: для каждого узла отдельно посчитать высоты обоих поддеревьев и сравнить.
Подсчет высоты поддерева – это обход всего поддерева, поэтому каждый узел обходится столько раз,
сколько у него предков, плюс один. На цепочке из n узлов это 1 + 2 + ... + n = n(n + 1)/2, то есть O(n²).

Но высота родителя выражается через высоты детей. Если обходить дерево снизу вверх, то к моменту
обработки узла высоты обоих его поддеревьев уже известны, и ни одну не нужно пересчитывать:
проверка узла и подсчет его высоты занимают O(1).

### Алгоритм

Порядок «сначала оба поддерева, потом сам узел» – это обратный обход (postorder). Функция
`postorder_heights(root)` делает его без рекурсии, на явном стеке, и для каждого узла выдает
тройку `(node, h_left, h_right)`. Внутри два списка:

- `stack` – что еще нужно сделать. Запись `(node, False)` значит «узел встречен впервые»,
  `(node, True)` – «оба поддерева уже обработаны»;
- `heights` – высоты уже обработанных поддеревьев, родитель которых еще не обработан.

Шаг цикла снимает запись со стека:

1. `(None, ...)` – пустое поддерево, кладем в `heights` высоту 0.
2. `(node, False)` – кладем на стек `(node, True)`, потом правого ребенка, потом левого.
   Стек – это LIFO, поэтому сначала полностью обработается левое поддерево, затем правое,
   и только потом снова дойдет очередь до `(node, True)`.
3. `(node, True)` – оба поддерева закончены, их высоты лежат на вершине `heights`: сверху правая
   (закончилась позже), под ней левая. Снимаем обе, выдаем `(node, h_left, h_right)` и кладем
   высоту узла `1 + max(h_left, h_right)`.

`is_balanced` перебирает эти тройки и на первом узле с `abs(h_left - h_right) > 1` возвращает `False`.
Генератор после этого больше не продвигается, поэтому остальные узлы не обходятся. Если нарушений
не нашлось, ответ `True`.

Отдельного значения для «здесь уже нарушение» (вроде `-1` вместо высоты) не нужно: нарушение
обнаруживается в `is_balanced` и сразу завершает проверку, а в `heights` лежат только настоящие высоты.

Обход выделен в генератор, чтобы визуализация и тесты смотрели на те же шаги, что делает
`is_balanced`, а не на отдельную копию алгоритма.

### Рекурсия или явный стек

Рекурсивный вариант того же обхода короче:

```python
def height_or_minus_one(node):
    if node is None:
        return 0
    left = height_or_minus_one(node.left)
    if left < 0:
        return -1
    right = height_or_minus_one(node.right)
    if right < 0 or abs(left - right) > 1:
        return -1
    return 1 + max(left, right)
```

Здесь `-1` не путается с высотой, потому что настоящие высоты неотрицательны. Время и память
у него те же O(n) и O(h). Но глубина рекурсии равна высоте дерева, а в Python она по умолчанию
ограничена примерно 1000 вызовами. Цепочка из нескольких тысяч узлов – вполне допустимое
бинарное дерево, и на ней этот вариант падает с `RecursionError`. Поднимать
`sys.setrecursionlimit` ненадежно: при слишком глубокой рекурсии можно переполнить
уже стек самого интерпретатора. Поэтому в решении явный стек: кода на несколько строк больше,
зато ограничение глубины снимается (тест `test_chain_deeper_than_recursion_limit` – цепочка из
100 000 узлов).

### Почему не сравнить глубины листьев

Иногда баланс подменяют условием «самый глубокий и самый мелкий листья отличаются не больше
чем на 1». Для произвольного дерева это не то же самое, и ошибка бывает в обе стороны:
цепочка из трех узлов имеет один лист (разброс 0), но не сбалансирована, а у минимального
сбалансированного дерева высоты 5 листья лежат на глубинах от 3 до 5. Оба случая есть в тесте
`test_leaf_depths_are_not_the_criterion`.

## Почему это правильно

**Порядок.** Узел выдается только из записи `(node, True)`, а она лежит на стеке под обоими
детьми, поэтому снимается, когда все поддеревья детей уже обработаны. Значит при обработке узла
высоты его детей посчитаны.

**Высоты на своих местах.** Обработка любого поддерева, пустого или нет, добавляет в `heights`
ровно одно число – его высоту, и при этом возвращает `heights` к тому, что было до начала,
плюс это число. Для пустого поддерева это видно сразу. Для непустого: левое поддерево добавляет
одно число, правое – одно, узел снимает оба и добавляет одно. Поэтому в момент `(node, True)` на
вершине `heights` лежат ровно высоты правого и левого поддеревьев этого узла, а не чужие числа.

**Инвариант.** Когда поддерево обработано, верно одно из двух:

- в `heights` лежит его правильная высота, и у всех его узлов условие баланса выполнено;
- нарушение уже найдено, и `is_balanced` вернула `False`.

Доказательство индукцией по высоте поддерева:

1. Пустое поддерево: высота 0 записана правильно, узлов в нем нет, проверять нечего.
2. Лист: оба поддерева пустые, `h_left = h_right = 0`, разность 0, высота 1. Лист сбалансирован.
3. Узел, у которого хотя бы одно поддерево несбалансировано: по предположению нарушение
   найдено при обработке этого поддерева, проверка уже завершилась с `False`. Это правильно:
   нарушение в любом узле поддерева – нарушение и во всем дереве.
4. Оба поддерева сбалансированы и их высоты h_L, h_R правильные: все узлы ниже текущего уже
   проверены, непроверенным остался только он сам, и для него нужны ровно h_L и h_R. Других
   данных о детях не требуется: баланс узла зависит только от высот поддеревьев, а их внутреннее
   устройство уже проверено.
5. Если |h_L – h_R| <= 1, условие выполнено у всех узлов поддерева, и его высота
   1 + max(h_L, h_R) – правильная по определению. Иначе текущий узел нарушает условие,
   и `is_balanced` возвращает `False`.

**Ответ.** Если цикл в `is_balanced` закончился без `False`, проверку прошел каждый узел, причем
с правильными высотами, значит дерево сбалансировано. Если какой-то узел нарушает условие, до
него обход дойдет (а раньше остановиться может только на другом нарушении), и ответ будет `False`.

Обход не меняет ни значения, ни ссылки: из узлов только читаются `left` и `right`, значения
(`val`) не читаются вовсе.

## Оценка сложности

Обозначения: `n` – число узлов, `h` – высота дерева.

| | `is_balanced` | пересчет высоты для каждого узла |
|---|---|---|
| время | O(n) | O(n²) в худшем случае |
| дополнительная память | O(h) | O(h) на рекурсию |

### Время

Каждый узел попадает на стек один раз как `(node, False)` и один раз как `(node, True)`,
каждая пустая ссылка – один раз как `(None, False)`. Пустых ссылок в дереве из n узлов ровно n + 1,
поэтому всего записей 3n + 1. Обработка одной записи – O(1): несколько `append`/`pop`, `max` от двух
чисел, сравнение. Итого O(n) в худшем случае. Тест `test_linear_work` считает обращения к
`left`/`right`: их ровно 2n, у оракула с пересчетом высот на цепочке из 500 узлов – больше 125 000.

Досрочный выход сокращает работу, если нарушение встречается рано (например, на цепочке
обход остановится на третьем снизу узле), но на оценку худшего случая не влияет: у
сбалансированного дерева обходятся все узлы, и на нем алгоритм делает Θ(n) работы.

### Память

Исходное дерево в оценку не входит. Дополнительно используются два списка:

- `stack`: на каждом уровне текущего пути от корня лежит запись `(node, True)` предка и, возможно,
  еще не начатый правый ребенок. Всего не больше 2h + 1 записей;
- `heights`: для каждого предка не больше одной готовой высоты левого поддерева, пока
  обрабатывается правое. Всего не больше h + 1 чисел.

Обе границы достигаются (левая цепочка для `stack`, правая для `heights`). Итого O(h):
O(log n) для сбалансированного дерева и O(n) для вырожденного, например цепочки. Высоты всех
узлов нигде не хранятся одновременно, словаря «узел -> высота» нет. O(1) памяти здесь не получить:
стек хранит путь от корня.

## Визуализация работы алгоритма

### Несбалансированное дерево

```
           10
          /  \
         5    15   <- нарушение: слева 0, справа 2
        / \     \
       3   8     18
      /            \
     1              20
```

```python
TreeNode(10,
         TreeNode(5, TreeNode(3, TreeNode(1)), TreeNode(8)),
         TreeNode(15, None, TreeNode(18, None, TreeNode(20))))
```

У корня высоты обоих поддеревьев равны 3, так что проверка только корня ответила бы `True`.
Нарушение в правом поддереве, у узла 15, у которого нет левого ребенка. Левое поддерево
обрабатывается первым и проходит проверку целиком, поэтому видно, как высоты передаются вверх.

Шаги – это ровно те тройки, которые `postorder_heights` выдает до остановки `is_balanced`
(тест `TestReadmeExample.test_unbalanced_table`):

| Шаг | Узел | Высота слева | Высота справа | Разность | Результат |
|---:|---:|---:|---:|---:|---|
| 1 | 1 | 0 | 0 | 0 | лист, высота 1 |
| 2 | 3 | 1 (узел 1) | 0 | 1 | ок, высота 1 + max(1, 0) = 2 |
| 3 | 8 | 0 | 0 | 0 | лист, высота 1 |
| 4 | 5 | 2 (узел 3) | 1 (узел 8) | 1 | ок, высота 3 |
| 5 | 20 | 0 | 0 | 0 | лист, высота 1 |
| 6 | 18 | 0 | 1 (узел 20) | 1 | ок, высота 2 |
| 7 | 15 | 0 | 2 (узел 18) | **2** | **нарушение, `is_balanced` возвращает `False`** |

Корень 10 не обрабатывается: проверка остановилась на шаге 7. Высоты его поддеревьев, 3 (узел 5)
и 3 (узел 15, если досчитать: 1 + max(0, 2)), алгоритм для корня так и не сравнивает, они приведены
только чтобы показать, что корень сам по себе выглядит сбалансированным
(тест `test_root_heights_hidden_by_early_exit`).

Ответ `False`, потому что условие должно выполняться у каждого узла, а у узла 15 оно нарушено.

### Сбалансированное, но не полное дерево

```
           1
          / \
         2   3
        / \   \
       4   5   6
      /
     7
```

Значения нарочно не образуют BST. Ни один внутренний узел не имеет равных высот поддеревьев,
у каждого разность ровно 1, и это допустимо (тест `test_balanced_table`):

| Шаг | Узел | Высота слева | Высота справа | Разность | Результат |
|---:|---:|---:|---:|---:|---|
| 1 | 7 | 0 | 0 | 0 | лист, высота 1 |
| 2 | 4 | 1 | 0 | 1 | ок, высота 2 |
| 3 | 5 | 0 | 0 | 0 | лист, высота 1 |
| 4 | 2 | 2 | 1 | 1 | ок, высота 3 |
| 5 | 6 | 0 | 0 | 0 | лист, высота 1 |
| 6 | 3 | 0 | 1 | 1 | ок, высота 2 |
| 7 | 1 | 3 | 2 | 1 | ок, высота 4 |

Все 7 узлов прошли проверку, ответ `True`.

## Тесты

`test_balanced_binary_tree.py`, 37 тестов. Запуск: `python -m unittest -v` из папки задачи.

Ожидаемый ответ в случайных тестах дает независимый оракул `naive_balanced`: он проходит все
узлы в ширину и для каждого заново считает высоты обоих поддеревьев отдельной рекурсивной
функцией, без досрочного выхода. Это другой порядок обхода и другой способ получить высоты,
O(n²), поэтому применяется только к небольшим деревьям.

| Класс | Что проверяется |
|---|---|
| `TestBasic` | пустое дерево, один узел, два узла с каждой стороны, корень с двумя листьями, полные деревья, не полное дерево из README, деревья Фибоначчи (разность ровно 1 у каждого внутреннего узла), очевидно несбалансированные; разность ровно 1 и ровно 2; возвращается именно `bool` (`assertIs`) |
| `TestEveryNode` | у корня разность <= 1, а нарушение глубже: пример из условия, нарушение в левом и в правом поддереве, у узла без одного ребенка, у листа на глубине 8 в полном дереве из 255 узлов, только у корня при сбалансированных половинах; разброс глубин листьев не равносилен балансу |
| `TestEdgeCases` | цепочки только из левых и только из правых детей, зигзаг; цепочки из 100 000 узлов (больше лимита рекурсии) с проверкой узла, где найдено нарушение; большие сбалансированные деревья (32 767 узлов, дерево Фибоначчи из 10 945 узлов, случайное) и большое с нарушением у корня |
| `TestValues` | одна форма с разными значениями: положительные, отрицательные, нули, повторы, не BST, случайные; значения, при сравнении которых тест падает; `None` в значении узла |
| `TestNoSideEffects` | после проверки те же узлы, значения и ссылки на детей (сравнение по `id`); повторные вызовы и чередование разных деревьев; поддерево несбалансированного дерева проверяется само по себе |
| `TestOracle` | все формы деревьев до 9 узлов (полный перебор, 6918 форм) и 1000 случайных деревьев до 60 узлов против оракула; 300 сбалансированных по построению деревьев, которые затем портятся подвешенной цепочкой |
| `TestHeights` | каждый узел выдается ровно один раз и после своих детей, высоты совпадают с оракулом; ссылки на детей читаются ровно 2n раз; после нарушения в левом поддереве правое не обходится |
| `TestReadmeExample` | обе таблицы визуализации целиком и высоты поддеревьев корня, не вычисленные из-за досрочного выхода |

Все случайные тесты используют `random.Random` с фиксированным seed и воспроизводятся. Весь набор
выполняется меньше чем за секунду.
