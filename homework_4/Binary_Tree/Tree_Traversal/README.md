# Задача 1. Tree Traversal

Нужно реализовать бинарное дерево поиска (BST) со вставкой, сохраняющей свойства BST,
и шесть обходов. Каждый обход возвращает список значений в порядке посещения.
Обозначения: `N` – посетить узел, `L` – обойти левое поддерево, `R` – правое.

| Обход | Метод | Порядок |
|---|---|---|
| preorder | `preorder()` | NLR |
| inorder | `inorder()` | LNR |
| postorder | `postorder()` | LRN |
| reverse preorder | `reverse_preorder()` | NRL |
| reverse inorder | `reverse_inorder()` | RNL |
| reverse postorder | `reverse_postorder()` | RLN |

## Файлы и запуск

| Файл | Что внутри |
|---|---|
| `main.py` | классы `Node` и `BinarySearchTree`: вставка `insert`, общий обход `_traverse` и шесть методов-обходов; интерактивный ввод: `parse_values`, `read_values`, `print_traversals`, `main` |
| `test_tree_traversal.py` | тесты |
| `README.md` | объяснение, сложность, визуализация |

```
python main.py              # спрашивает числа, строит BST и печатает шесть обходов
python -m unittest -v       # тесты, запускать из папки задачи
```

### Интерактивный запуск

`python main.py` просит ввести целые числа через пробел, вставляет их в дерево в порядке ввода
и печатает все шесть обходов. Пример – значения из раздела "Визуализация":

```
Введите целые числа через пробел: 41 20 65 11 29 91 32 72 26 29
preorder           [41, 20, 11, 29, 26, 32, 29, 65, 91, 72]
inorder            [11, 20, 26, 29, 29, 32, 41, 65, 72, 91]
postorder          [11, 26, 29, 32, 29, 20, 72, 91, 65, 41]
reverse_preorder   [41, 65, 91, 72, 20, 29, 32, 29, 26, 11]
reverse_inorder    [91, 72, 65, 41, 32, 29, 29, 26, 20, 11]
reverse_postorder  [72, 91, 65, 29, 32, 26, 29, 11, 20, 41]
```

Граничные случаи:

| Ввод | Что происходит |
|---|---|
| пустая строка (просто Enter) | пустое дерево, все шесть обходов печатают `[]` |
| `7` | дерево из одного узла, все обходы `[7]` |
| `-3 0 -3` | отрицательные числа, ноль и повторы допустимы; повтор уходит вправо, как и при вставке из кода |
| `1 abc 2.5` | `Ошибка: не целые числа: abc, 2.5. Повторите ввод.` – и вопрос задается снова |
| Ctrl+D или Ctrl+C | `Ввод прерван.`, программа завершается без трассировки |

Число – все, что принимает `int()`: допустимы знак (`-5`, `+5`) и лишние пробелы или табуляции
между числами, а `2.5`, `1e3` и `1,2` считаются ошибкой.

Пример с ошибкой:

```
Введите целые числа через пробел: 5 q
Ошибка: не целые числа: q. Повторите ввод.
Введите целые числа через пробел: 5 3 8
preorder           [5, 3, 8]
inorder            [3, 5, 8]
postorder          [3, 8, 5]
reverse_preorder   [5, 8, 3]
reverse_inorder    [8, 5, 3]
reverse_postorder  [8, 3, 5]
```

Вопрос задается только при запуске `python main.py` (блок `if __name__ == "__main__"`).
При `import main` ничего не спрашивается, и дерево по-прежнему можно строить прямо в коде:
`BinarySearchTree([41, 20, 65])` или через `insert`. Функции `read_values` и `main` принимают
функции ввода и вывода параметрами (по умолчанию `input` и `print`), так их проверяют тесты.

## Объяснение решения

### Устройство дерева

`Node` хранит `value`, `left` и `right`. `BinarySearchTree` хранит только `root`
(`None` у пустого дерева). Конструктор принимает необязательную последовательность значений
и вставляет их по одной, так что `BinarySearchTree(values)` – то же самое, что цикл из `insert`.

Значения могут быть любыми, которые сравниваются через `<`: в тестах это целые числа,
в том числе отрицательные, ноль и числа порядка 10^30.

### Повторяющиеся значения

Условие не говорит, что делать с дубликатами. Выбрано так: равное значение уходит вправо
и хранится в отдельном узле. Это то же правило, что в `TREE-INSERT` у Кормена (`if z.key < x.key`
влево, иначе вправо). Инвариант дерева при этом такой:

> для каждого узла все значения его левого поддерева **строго меньше** значения узла,
> а все значения правого поддерева **больше либо равны** ему: `left < node <= right`.
> Ограничение действует относительно всех предков, а не только родителя.

Это единое определение BST для задач 1 и 2: задача 2 (Validate BST) проверяет дерево ровно по
нему, поэтому любое дерево, построенное здесь через `insert`, в том числе с повторами, она
признает корректным (например, дерево из раздела "Визуализация").

Почему не другие варианты:

- игнорировать повтор (дерево как множество) – тогда обход теряет кратность, и `inorder`
  перестает быть сортировкой вставленных значений;
- счетчик в узле – лишнее поле, и каждый обход должен был бы выдавать значение несколько раз.
  Для задачи про обходы это усложнение без пользы.

При выбранном правиле длина любого обхода равна числу вызовов `insert`, и это проверяется тестами.

### Вставка

`insert` создает узел `new_node` и спускается от корня циклом: если `value < node.value`,
идет в `node.left`, иначе в `node.right`. Как только нужная ссылка оказалась `None`,
туда подвешивается `new_node`. Рекурсии нет, повторных проходов по дереву тоже: один спуск
от корня до места вставки.

### Обходы

Все шесть методов вызывают один `_traverse(order)`, где `order` – строка из таблицы выше:
`preorder` это `_traverse("NLR")`, `reverse_postorder` это `_traverse("RLN")` и т.д.
Так строки в коде буквально совпадают с определениями, а перепутать обратные обходы можно
только в одном месте, которое видно глазами.

`_traverse` работает на явном стеке пар `(node, ready)`:

- `(node, False)` – поддерево `node` еще не разобрано. Когда такая пара снимается со стека,
  на стек кладутся части узла по `order`: для `N` – пара `(node, True)`, для `L` и `R` –
  соответствующий ребенок с `False`, если он есть;
- `(node, True)` – пора посетить узел: `node.value` дописывается в `result`.

Стек снимает элементы в обратном порядке, поэтому части кладутся с конца `order`
(`reversed(order)`): для `"LRN"` сначала кладется `N`, потом `R`, потом `L`, и снимется
первым `L`.

`result` создается заново при каждом вызове, а дерево только читается, поэтому повторные
вызовы независимы и обходы ничего не меняют.

### Почему это правильно

**Вставка, пустое дерево.** `root` становится новым узлом без детей. В дереве один узел,
у него нет поддеревьев, инвариант выполнен.

**Вставка в непустое дерево.** Узлы, в чьих поддеревьях окажется новый лист, – это ровно
узлы на пути спуска. На каждом из них `insert` выбирает сторону по тому же сравнению, что
и инвариант: влево только при `value < node.value`, вправо при `value >= node.value`.
Значит новое значение удовлетворяет условию каждого узла на пути. Остальные поддеревья
не меняются, а меняется ровно одна ссылка – та, что была `None`. Новый узел – лист, для
него условие выполнено. Спуск конечен: каждый шаг опускается на уровень ниже.

Отсюда же видно, где окажется повтор. Если `b == a` и `a` уже в дереве, то `b` на каждом
узле пути к `a` делает тот же выбор, что сделало бы `a`, доходит до `a` и уходит вправо.
То есть более поздний дубликат всегда в правом поддереве более раннего (в примере ниже
второе 29 лежит под первым).

**Обходы.** Утверждение: если со стека снята пара `(node, False)`, то следующие действия
`_traverse` допишут в `result` в точности обход поддерева `node` по `order`, после чего стек
будет таким же, каким был под этой парой.

Индукция по размеру поддерева. Части `node` кладутся в обратном порядке, значит снимаются
в порядке `order`. Часть `N` сразу дает `node.value`. Часть-ребенок по предположению индукции
выдает весь обход своего поддерева и возвращает стек к оставшимся частям `node`.
Отсутствующий ребенок не кладется, и это соответствует пустому поддереву, у которого обход
пустой. Когда все части сняты, стек вернулся к исходному.

Для корня это и есть определение обхода. Отсюда:

- **все узлы посещаются:** каждый ребенок попадает на стек при разборе своего родителя,
  начиная с корня;
- **каждый ровно один раз:** у узла один родитель, поэтому `(node, False)` кладется один раз,
  и при его разборе ровно один раз кладется `(node, True)`;
- **порядок N, L, R соблюден:** части снимаются в порядке `order`, а поддерево целиком
  выдается до перехода к следующей части.

**inorder по неубыванию.** `inorder(node) = inorder(L) + [node.value] + inorder(R)`. По инварианту
все значения в `L` меньше `node.value`, а все в `R` не меньше. Если обе части уже по
неубыванию (индукция), то и весь список по неубыванию. Для `reverse_inorder`
(`R`, `N`, `L`) то же рассуждение дает невозрастание.

### Почему явный стек, а не рекурсия

| Вариант | Плюсы | Минусы |
|---|---|---|
| рекурсия, три строки на обход | самый короткий и понятный код | глубина вызовов равна высоте дерева. Лимит в Python 1000 кадров, а 1000 вставок по возрастанию уже дают цепочку такой глубины – `RecursionError`. `sys.setrecursionlimit` меняет глобальную настройку и может уронить интерпретатор на переполнении стека C |
| шесть отдельных итеративных алгоритмов | без лишних кортежей на стеке | у каждого своя логика (postorder через указатель на последний посещенный узел или два стека), шесть разных циклов труднее проверить и легко перепутать |
| обход Морриса | O(1) дополнительной памяти | временно перевешивает ссылки дерева, а обходы по условию дерево менять не должны |
| **один `_traverse(order)`** | один цикл на 15 строк, работает на любой глубине, порядок задан строкой из определения | константа хуже, чем у рекурсии: на каждый узел два кортежа и цикл по `order` |

Асимптотика у рекурсии и выбранного варианта одинаковая (см. ниже), разница только в том,
что стек лежит в куче, а не в стеке вызовов, и не упирается в лимит.

Отдельно: `reverse_preorder` (NRL) совпадает с перевернутым `postorder` (LRN), а
`reverse_postorder` (RLN) – с перевернутым `preorder` (NLR). Обходы так **не** реализованы,
каждый честно идет по дереву в своем порядке. Но тесты используют эти тождества как
дополнительную независимую проверку.

## Оценка сложности

Обозначения: `n` – число узлов, `h` – высота дерева, число узлов на самом длинном пути от корня
до листа (у пустого дерева `h = 0`, у одного узла `h = 1`). Всегда `log2(n + 1) <= h <= n`.

Обычное BST не балансируется, поэтому `h` зависит только от порядка вставок.

| Форма дерева | `h` |
|---|---|
| пустое | 0 |
| сбалансированное по высоте (у каждого узла высоты поддеревьев отличаются не больше чем на 1) | O(log n) |
| вырожденное (цепочка, например после вставок по возрастанию) | n |

### Вставка одного элемента

| | Время | Доп. память |
|---|---|---|
| пустое дерево | O(1) | O(1) |
| в общем случае | O(h): одно сравнение на каждый узел пути, путь не длиннее `h` | O(1) |
| сбалансированное по высоте | O(log n) | O(1) |
| вырожденное | O(n) | O(1) |

Память O(1), потому что спуск – цикл с одной переменной `node`, без рекурсии.
Сам новый узел тоже O(1).

### Построение дерева из n вставок

`k`-я вставка делает столько сравнений, какова глубина нового узла, а она не больше `k - 1`.

- **Худший случай – O(n²).** Если значения приходят по возрастанию (или по убыванию),
  каждое новое становится правым (левым) ребенком самого глубокого узла, и `k`-я вставка
  делает ровно `k - 1` сравнений. Всего `0 + 1 + ... + (n - 1) = n(n - 1) / 2` – это Θ(n²).
  Повторяющееся одно значение `x, x, x, ...` дает тот же худший случай: все уходят вправо.
- **Если дерево на всем протяжении остается сбалансированным по высоте** – O(n log n).
  Это не гарантия, а свойство конкретного порядка вставок.
- **Случайный порядок различных значений** (все перестановки равновероятны): ожидаемая глубина
  узла O(log n), ожидаемое время построения O(n log n). Это оценка в среднем при
  предположении о входе, а не гарантия для любого входа.

Память: O(n) на узлы, дополнительно O(1).

### Обходы

Для всех шести обходов оценка одна и та же, они отличаются только строкой `order`.

**Время Θ(n).** Каждый узел ровно один раз кладется на стек как `(node, False)` и ровно один
раз как `(node, True)`, то есть всего `2n` операций `push` и `2n` операций `pop`. Разбор узла –
цикл из трех итераций по `order`. Итого O(n), и меньше нельзя, потому что каждый узел
записывается в ответ.

**Память под ответ Θ(n)** – возвращаемый список из `n` значений.

**Дополнительная память на стек O(h).** В стеке лежат только еще не снятые части узлов на
пути от корня до узла, который разбирается сейчас. После разбора узла из трех его частей одна
снимается сразу, поэтому у каждого узла пути остается не больше двух. Отсюда размер стека
не больше `2h + 1`. В примере ниже (`h = 5`) максимум – 6 элементов.

| Форма дерева | Время | Ответ | Стек |
|---|---|---|---|
| пустое | O(1) | O(1) | O(1) |
| сбалансированное по высоте | Θ(n) | Θ(n) | O(log n) |
| вырожденное | Θ(n) | Θ(n) | O(n) |

Рекурсивный обход имел бы те же O(h) дополнительной памяти, только в стеке вызовов,
поэтому O(1) это не было бы ни в одном из вариантов.

## Визуализация

### Построение дерева

Значения вставляются в порядке `41, 20, 65, 11, 29, 91, 32, 72, 26, 29`. Второе 29 обозначено
`29'`, чтобы его было видно на схеме и в таблицах; в дереве это обычное число 29.

| Шаг | Значение | Путь спуска | Куда встает |
|---:|---:|---|---|
| 1 | 41 | дерево пустое | корень |
| 2 | 20 | 41 ← | левый ребенок 41 |
| 3 | 65 | 41 → | правый ребенок 41 |
| 4 | 11 | 41 ←, 20 ← | левый ребенок 20 |
| 5 | 29 | 41 ←, 20 → | правый ребенок 20 |
| 6 | 91 | 41 →, 65 → | правый ребенок 65 |
| 7 | 32 | 41 ←, 20 →, 29 → | правый ребенок 29 |
| 8 | 72 | 41 →, 65 →, 91 ← | левый ребенок 91 |
| 9 | 26 | 41 ←, 20 →, 29 ← | левый ребенок 29 |
| 10 | 29' | 41 ←, 20 →, 29 →, 32 ← | левый ребенок 32 |

Итоговое дерево (`h = 5`):

```
                41
             /      \
           20        65
          /  \         \
        11    29        91
             /  \       /
           26    32   72
                /
              29'
```

Здесь есть все типы узлов: с двумя детьми (41, 20, 29), с одним (65, 91, 32) и листья
(11, 26, 29', 72). Эту структуру целиком, как вложенные кортежи, проверяет тест
`TestInsert.test_readme_shape`.

### Вставка 29' по шагам

Самая длинная вставка, к тому же с равным значением:

| Текущий узел | Сравнение | Решение |
|---|---|---|
| 41 | `29 < 41` | влево, `41.left` = 20 не пуст, спускаемся |
| 20 | `29 < 20` ложно | вправо, `20.right` = 29 не пуст, спускаемся |
| 29 | `29 < 29` ложно | **равное – вправо**, `29.right` = 32 не пуст, спускаемся |
| 32 | `29 < 32` | влево, `32.left` пуст – **создаем узел**, `32.left = new_node` |

Проверка инварианта для нового листа: он в левом поддереве 41 (29 < 41), в правом поддереве 20
(20 <= 29), в правом поддереве первого 29 (29 <= 29) и в левом поддереве 32 (29 < 32).
Изменилась одна ссылка `32.left`.

### Шесть обходов

| Шаг | preorder NLR | inorder LNR | postorder LRN | reverse preorder NRL | reverse inorder RNL | reverse postorder RLN |
|---:|---:|---:|---:|---:|---:|---:|
| 1 | 41 | 11 | 11 | 41 | 91 | 72 |
| 2 | 20 | 20 | 26 | 65 | 72 | 91 |
| 3 | 11 | 26 | 29' | 91 | 65 | 65 |
| 4 | 29 | 29 | 32 | 72 | 41 | 29' |
| 5 | 26 | 29' | 29 | 20 | 32 | 32 |
| 6 | 32 | 32 | 20 | 29 | 29' | 26 |
| 7 | 29' | 41 | 72 | 32 | 29 | 29 |
| 8 | 65 | 65 | 91 | 29' | 26 | 11 |
| 9 | 91 | 72 | 65 | 26 | 20 | 20 |
| 10 | 72 | 91 | 41 | 11 | 11 | 41 |

Все шесть столбцов проверяет тест `TestReadmeExample.test_traversals`.

Что видно по таблице:

- в NLR и NRL корень 41 первый, в LRN и RLN – последний: родитель везде после детей
  (32 после 29', 91 после 72, 20 после всего своего поддерева);
- NRL и RLN совсем разные: NRL начинается с корня и идет по правой ветке вниз (41, 65, 91, 72),
  RLN начинается с самого глубокого узла правой ветки (72) и поднимается;
- inorder дает значения по неубыванию, reverse inorder – по невозрастанию. Первое 29 идет в inorder
  раньше 29', потому что 29' лежит в его правом поддереве.

### Ход postorder на стеке

Как `_traverse("LRN")` проходит это дерево. Запись `29` – пара `(узел, False)`, узел еще
не разобран; `[29]` – пара `(узел, True)`, узел пора записать. Вершина стека справа.

| Снято со стека | Действие | Стек после шага |
|---|---|---|
| 41 | разложить: кладем `[41]`, 65, 20 | `[41] 65 20` |
| 20 | разложить | `[41] 65 [20] 29 11` |
| 11 | разложить, детей нет | `[41] 65 [20] 29 [11]` |
| [11] | записать **11** | `[41] 65 [20] 29` |
| 29 | разложить | `[41] 65 [20] [29] 32 26` |
| 26 | разложить, детей нет | `[41] 65 [20] [29] 32 [26]` |
| [26] | записать **26** | `[41] 65 [20] [29] 32` |
| 32 | разложить, правого ребенка нет | `[41] 65 [20] [29] [32] 29'` |
| 29' | разложить, детей нет | `[41] 65 [20] [29] [32] [29']` |
| [29'] | записать **29'** | `[41] 65 [20] [29] [32]` |
| [32] | записать **32** | `[41] 65 [20] [29]` |
| [29] | записать **29** | `[41] 65 [20]` |
| [20] | записать **20** | `[41] 65` |
| 65 | разложить, левого ребенка нет | `[41] [65] 91` |
| 91 | разложить, правого ребенка нет | `[41] [65] [91] 72` |
| 72 | разложить, детей нет | `[41] [65] [91] [72]` |
| [72] | записать **72** | `[41] [65] [91]` |
| [91] | записать **91** | `[41] [65]` |
| [65] | записать **65** | `[41]` |
| [41] | записать **41** | пусто |

Здесь видно, как родитель оказывается после детей. При разборе 20 метка `[20]` кладется
на стек **под** обоими детьми, поэтому снимется только когда оба поддерева будут выписаны
целиком. То же с 41: `[41]` лежит на дне стека весь обход. Максимальный размер стека – 6
(например, сразу после разбора 29), в пределах оценки `2h + 1 = 11`.

## Тесты

`test_tree_traversal.py`, 48 тестов в восьми классах. Запуск из папки задачи: `python -m unittest -v`,
все проходят примерно за секунду.

Независимые эталоны: рекурсивные обходы, написанные прямо по определению
(`[node.value] + ref_preorder(node.left) + ref_preorder(node.right)` и т.п., шесть отдельных функций),
`sorted` для inorder и reverse inorder, `Counter` для кратности значений. Инвариант BST проверяется
через границы `lo <= value < hi`, которые узел получает от всех предков, то есть для всех
поддеревьев, а не только для детей.

Кроме того, я проверил, что тесты ловят типичные ошибки: если поменять местами строки `"NRL"` и

`_traverse` на рекурсивный, падают оба теста на глубоких цепочках с `RecursionError`.

ошибки, без обработки EOF или с сортировкой введенных чисел перед вставкой тоже падают тесты.

## Ограничения

- Дерево не балансируется, как и требует условие, поэтому на упорядоченных входах вставка
  стоит O(n), а построение – Θ(n²). Обходы при этом работают на любой глубине: стек хранится
  в списке, а не в стеке вызовов.
- Значения должны сравниваться через `<`. Смешивать, например, числа и строки нельзя –
  будет `TypeError` при вставке, как и у `sorted`.
